# UI/UX & Visual Product Quality

## Purpose

Create an intentional, polished, accessible, product-specific experience rather than a generic AI-generated interface.

## Design Process

Understand user goals → information architecture → user journeys → interaction model → visual direction → design system → components → states → motion → responsive behavior → accessibility → visual review.

## Visual Direction

Define where appropriate:

- Brand personality
- Visual language
- Color system
- Typography
- Spacing
- Grid/layout
- Component hierarchy
- Iconography
- Imagery/illustration
- Surface treatment
- Depth and hierarchy
- Dark/light themes

Use established design references as inspiration, but do not clone another product. The interface should have its own reasoned visual identity.

## Motion & Animation

Animation is a product tool, not decoration. Use motion for feedback, hierarchy, continuity, orientation, storytelling, onboarding, or delight. Avoid random animation and unnecessary movement. Respect reduced-motion preferences.

## Required States

Consider loading, empty, error, success, disabled, partial data, permission denied, offline/degraded, validation, first-use, returning-user, and destructive-action states where relevant.

## Responsive Experience

Desktop and mobile should feel intentionally designed. Do not merely shrink the desktop layout. Adapt interaction patterns, navigation, density, controls, and content hierarchy to the device.

## Accessibility

Consider semantic structure, keyboard navigation, focus visibility, contrast, screen readers, reduced motion, forms, labels, error communication, touch targets, and other applicable accessibility requirements.

## Visual Quality Gate

Before considering a user-facing phase complete, evaluate:

- Does the interface look intentionally designed?
- Does the visual language fit the product?
- Does motion improve the experience?
- Are transitions and micro-interactions polished?
- Are states complete?
- Is hierarchy clear?
- Does the product avoid generic AI-template patterns?
- Does responsive behavior feel native to each device class?
