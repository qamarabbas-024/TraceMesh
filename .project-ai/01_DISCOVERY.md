# Discovery & Problem Definition

## Purpose

Turn a raw idea into a clearly defined product problem before implementation.

## Required Flow

Raw idea → clarify the problem → identify users → map use cases → understand current solutions → identify constraints → validate feasibility → define the opportunity → recommend direction.

## Discovery Questions

Determine:

- What problem are we solving?
- Who experiences it?
- How frequently and painfully does it occur?
- What do people use today?
- Why are current solutions insufficient?
- What outcome does the user actually want?
- What would make a user switch?
- What assumptions are unverified?
- What constraints exist: technical, financial, legal, time, platform, privacy, or operational?

## Do Not Build Yet

When given a raw idea, do not immediately create the implementation. First produce a concise product understanding, research findings, major risks, proposed scope, and recommended direction.

## Problem Quality Test

Avoid building a solution simply because it is technically interesting. State the problem in user terms, define measurable success where possible, and explain why the proposed product should exist.

## Discovery Output

For an approved project concept, maintain:

- Problem statement
- Target users/personas
- Primary jobs-to-be-done
- Core use cases
- Constraints
- Assumptions
- Unknowns
- Success criteria
- Initial scope
- Out-of-scope items
